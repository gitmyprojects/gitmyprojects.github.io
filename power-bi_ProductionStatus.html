Production Status Board

Power BI · ERP and SharePoint data · Conditional formatting · Wolf Industries

Approach highlighted

One view of the production queue from two sources. Job status comes from the ERP, actual start and end dates come from a SharePoint list the production team maintains, and the report joins them so nobody has to check both.

Project Summary
The report gives production and office staff one view of the production queue: which jobs are finished, which are on the floor and which haven't started, along with purchasing notes that can affect the schedule.

How It Works

  • Two sources, one row per job. The ERP job feed supplies the job number, production status and purchasing notes. A SharePoint production queue list supplies the description and the actual start and end dates. The model relates them on the job, so each row shows both.
  • Status that reads from across the room. Conditional formatting colors each status: green for complete, yellow for in progress and red for not started.
  • Running totals. Cards show jobs completed all time, this year and this quarter, plus how many are in progress and not started.
  • Long text kept readable. Descriptions and purchasing notes are truncated in the data so the table stays one line per job.

Skills Demonstrated
Power BI Desktop, combining ERP and SharePoint data in one model, relationships, conditional formatting, KPI cards, and report design for a production audience.
